# プロダクト方針

## Vision

Personal Engineering Task Managerは、エンジニア本人が毎日開き、仕事の流れを把握し、「次に何を進めるか」を迷わず決めるための個人用ワークスペースです。

チーム全体のプロジェクト管理を置き換えるのではなく、GitHub Issues、チケット管理、チャットなどに分散した自分の作業を、日々の実行単位へ落とし込むことに集中します。

## コアとなるワークフロー

1. 取り組むタスクを「今日やること」へ置く
2. 着手したら「進行中」へ移す
3. PR作成など他者の確認が必要になったら「レビュー待ち」へ移す
4. 外部要因で進められない場合は理由付きで「ブロック中」へ移す
5. 完了した仕事を「完了」へ移す

内部ステータスは表示名から分離し、`today`、`in_progress`、`in_review`、`blocked`、`done`として固定します。

## 初期スコープ

- 5ステータスを横断して確認できるボード
- タスクの追加・編集・削除・ステータス変更
- 優先度、プロジェクト、タグ、期限、ブロック理由
- 検索と絞り込み
- ブラウザを閉じても残るローカル永続化

## スコープ外（当面）

- チームメンバーへのアサインや権限管理
- 複雑なスプリント・工数・予算管理
- リアルタイム共同編集

## 実装ロードマップ

### Phase 1: 日常利用できる最小構成

- タスク編集・削除と任意ステータスへの移動
- localStorageによる永続化
- 今日の日付を基準にした表示
- 空状態、入力エラー、キーボード操作の改善

### Phase 2: エンジニアリング文脈の強化

- GitHub Issue / Pull Request URLの保持
- レビュー待ち時間、ブロック時間の可視化
- Markdownメモ、チェックリスト
- 完了タスクのアーカイブ

### Phase 3: 外部サービス連携

- GitHubから自分に関連するIssue / PRを取り込む
- カレンダーや通知との連携
- データのエクスポート / インポート

## 設計上の判断

- UIから独立した`EngineeringTask`型をドメインモデルの中心にする
- Recoil atomを状態の単一の入口にし、集計はselectorで導出する
- 初期サンプルデータにより、各ステータスの意図を起動直後に確認できるようにする
- 旧チュートリアルコードは一度に削除せず、移行完了後に整理する
